## Assumptions and Clarifications

- Candidate text receives no normalization, length limit or fuzzy comparison because none is
  approved for I02.
- Exact revision comparison includes all eligible Context Items and detects insert, update and
  predicate exit. A short PostgreSQL `SHARE` table lock closes the phantom-insert race only during
  the final transaction.
- A failed response returned by `AIExecutionPort` is metered. The existing G01 exception contract
  intentionally carries no provider/token/cost metadata, so I02 does not invent Usage values for
  an exception raised before a structured response exists.
- The Outbox payload omits `conflict_group_key`; the approved minimum safe identifiers are enough
  and avoid treating an opaque model key as persistent business data.
- Replay returns current Requirements generated by a same-tenant succeeded Job, not an immutable
  historical payload. A succeeded Job with zero generated rows is a valid empty terminal replay;
  failed Jobs replay their stored safe error. This is the owner clarification dated 2026-09-07.
- **Unapproved assumptions:** None

## Changes

- Added shared framework-free `GenerateRequirementsUseCase`, ports, candidate/snapshot/result value
  objects, validation, repair, metering, exact merge and replay behavior.
- Extended Requirement persistence with `is_unsupported`, `duplicate_group_key` and nullable,
  non-unique `generation_job_id`; added the tenant-first replay index and restrictive Job FK in
  migration `0012_requirement_generation`.
- Added tenant-scoped SQLAlchemy snapshot/read/merge persistence and a Unit of Work that atomically
  commits Requirement writes/provenance unions with conflict Outbox events.
- Added a thin Worker task wrapper and deterministic fake-provider Application tests.
- Extended the structured-log allowlist only with approved version/count fields; no content fields
  were admitted.
- Added ADR-031, contract tests and synchronized module, migration, data-model and architecture
  mirrors.

## Structure Preservation

- Preserved `Worker → shared Application Use Case → Ports ← Infrastructure` and kept Domain and
  Application independent of FastAPI, SQLAlchemy, Celery, Redis and provider SDKs.
- Reused the existing AIExecutionPort, UsageLedger, Requirement table, Job identity and generic
  transactional Outbox. No deployable, public route, Queue contract, Provider adapter, Gap model or
  conflict table was added.
- Cross-module Context access is read-only; Requirement and Outbox writes are coordinated by one
  Application Unit of Work.
- Existing I01 human-owned fields and removed lifecycle semantics remain intact.

## Senior Review

- **Contract parity:** PASS. Candidate fields, unsupported rule, exact duplicate equality, first
  confidence, stable provenance union, zero-or-one Repair and final Job-gated replay match ADR-031.
- **Atomicity/races:** PASS. AI runs outside the DB transaction; the short final transaction locks
  Project then Context Items, compares the exact eligible revision set, and commits Requirement
  changes plus conflict Outbox together. Forced Outbox failure rolls all business changes back.
- **Tenant/security:** PASS. Snapshot, existing Requirement mutation, terminal Job lookup and replay
  all require the same Account and Project. A caller-supplied Job UUID is never Tenant authority.
- **Idempotency/merge:** PASS after correction. Replay now requires same-tenant Job status
  `succeeded|failed`, including an empty succeeded result. A second check before persistence handles
  a terminal result that appears after AI. Existing user fields and removed state are never
  overwritten or reactivated.
- **Observability/privacy:** PASS after testing the production structured logger. Only approved
  versions, counts, identifiers, duration and reason codes survive its allowlist; Requirement,
  Context, prompt, output and provenance content are dropped.
- **Migration/recovery:** PASS on PostgreSQL 16. The non-unique tenant-first replay index and
  restrictive Job FK match the contract; downgrade to 0011 and re-upgrade to head both passed.
- **Performance/locking:** PASS for Sprint 1. Replay uses the Job primary key and tenant-first
  Requirement index. The exact-set `SHARE` lock is held only in the short post-AI transaction and is
  explicitly tracked as a contention risk rather than hidden.
- **Scope:** PASS. No result/batch/conflict/Gap table, immutable historical payload, public route,
  provider adapter, Queue transport or UI behavior was introduced.
