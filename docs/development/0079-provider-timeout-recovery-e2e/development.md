## Changes

- Accepted ADR-065 and linked it in the ADR index.
- Added explicit Coordinator-managed mode to AI-01. The constructor rejects
  missing or simultaneous Usage owners; the pre-existing Workflow-owned path
  remains unchanged. The Workflow does not construct or append a second
  UsageRecord for Coordinator-managed invocations.
- Extended the isolated 0077 harness with an opt-in timeout-then-success Fake
  Provider. The existing 0069 Coordinator owns both invocation records using
  the real PostgreSQL Ledger under `aria_worker`. The API-side test owner
  verifies two distinct attempt IDs, retry numbers 0/1, the same Job,
  `failed/unavailable` with NULL token/cost fields, and `success/complete`.
- Corrected the Ledger's `ON CONFLICT DO NOTHING` to omit a conflict target.
  This preserves attempt-ID idempotency without a new table privilege; a
  direct PostgreSQL regression now inserts and replays under `aria_worker`.
- Added a dedicated `npm run test:provider-timeout-recovery-e2e` command. It
  reruns the unchanged 0077 journey and its PostgreSQL negative gates before
  the 0079 scenario. Updated the 0069 static contract test to match the
  least-privilege insert proven by the new runtime test.

## Architecture and Design Decisions

See ADR-065. No new Provider, schema, service or public route is introduced.
The targetless conflict clause remains safe with the current Usage table:
`provider_attempt_id` is the sole caller-supplied unique identity; `id` is
generated by PostgreSQL. Duplicate persistence still emits no second metric.

## Structure Preservation

PASS. Existing modular-monolith layering, AIExecutionPort, Job/Outbox/Relay,
Queue envelope, Worker principal, Source/Context persistence and the direct
Workflow metering path are preserved. The Coordinator adapter exists only in
`tests/e2e/`; it is not composed into hosted or product runtime. No migration,
grant, RLS policy, automatic retry or public endpoint was added.

## Senior Review

- **Accounting and recovery:** PASS. Two actual invocations have distinct
  attempt IDs and exactly two durable rows; the first records unknown Usage as
  NULL, never zero. Duplicate Job delivery and same-attempt Ledger persistence
  remain idempotent. No Fallback or second Job is created.
- **Least privilege:** PASS. The first E2E run exposed a previously untested
  `42501` failure: an explicit `ON CONFLICT(provider_attempt_id)` target
  required privilege beyond Worker INSERT. Targetless `DO NOTHING` passed
  under the real `aria_worker` role; no broad grant was made. The direct
  Worker-role regression proves one row and one metric after two appends.
- **Privacy and scope:** PASS. The Queue still contains identifiers only;
  controlled logs and process output reject synthetic fixture content. No
  real Provider, customer data, paid call or Hosted activation was used.
- **Corrections during review:** Added an exact synthetic price-fixture check
  so an earlier immutable row cannot silently change the test's cost basis;
  rejected the timeout flag for other stages; removed temporary SQLSTATE
  diagnostics before final verification. Full lint, typecheck and tests passed.
